# 0003: 实例寻址——项目路径为句柄，运行时不单独寻址

中文 | [English](0003-instance-addressing.en.md)

> 当前会话工具面、默认目标与通知限制见 [daemon README](../../plugin/godot-mcp-unified/server-dotnet/README.md) 及 ADR-0006～0008；下文保留最初迁移方案及修订历史。


需要实例目标的工具带可选 `instance` 参数，主标识为规范化项目路径（`list_instances` 同时提供短 id 别名）；恰好一个活跃实例时隐式选中，多个且未指定时报错并列出实例清单。运行时实例不作为独立句柄——`game_start(instance: X)` 之后 `animation_player_control(instance: X)` 自动路由到 X 的运行时通道，编辑器实例是唯一句柄。同一项目双开编辑器在一期明确不支持（注册表以项目路径为主键，文档写明，不做报错优化）。

## Considered Options

- SDK stateful 模式下的会话级 `use_project` 绑定：体验像"当前目录"，但走 legacy 兼容路径，与 2026-07-28 无状态核心的方向相悖，且后续拆除困难。
- 运行时实例独立句柄：句柄面翻倍，会话需要理解编辑器/运行时两套标识，收益只有"绕过编辑器直接打游戏进程"这一非目标场景。

## Consequences

- 单次调用只允许单目标；跨实例批量（扇出）一期不做，留作后续语法糖（部分失败语义、顺序保证都是新增负担）。
- 实例间引擎版本/扩展能力不一致时，`tools/list` 呈现并集，调用落在不支持该工具的实例上时返回带引擎版本说明的明确错误（stateless 协议下不存在"按谁过滤"的全局答案，交集会被单个旧实例降级整个会话）。

## 修订记录

### 2026-10-25：新增 per-key 默认目标（见 0008）

本文"多实例且未指定时报错"的规则仍然保留，但在它之前插入了**本键默认目标**这一层：会话用
`godot_connect` 写入默认目标后，省略 `instance` 的调用直接落到该目标，不再报错。
Considered Options 里 `use_project` 一条的理由（"与无状态核心相悖"）在 0006 的自有会话键
落地后不再成立——键由传输层承载，不依赖任何协议会话语义。详见 [0008](0008-per-key-default-target.md)。
