# 测试并行度与证据范围

中文 | [English](TESTING-NOTES.en.md)

## 当前配置

xunit.runner.json 的 maxParallelThreads 为 1，且关闭测试集合并行，并由测试 csproj 复制到输出。多数集成测试启动独立 daemon/shim 进程、随机端口和临时状态目录；并行度限制用于控制资源与时间窗口竞争，不替代故障分析。

此前记录过 196/196 通过的串行与并行运行。这只能证明当时断言的输入/序列通过，不能推导每个测试逻辑都正确，也不能证明没有产品缺陷。当前通知、组替换/重放和在途目标的未覆盖问题见 [daemon README](../../README.md)。

## 定位不稳定失败

1. 保留首次失败输出、测试名、配置、端口与进程状态。
2. 对失败测试定向重跑，并按需要比较串行/并行结果。
3. 串行通过只说明调度/资源竞争相关，不能自动排除产品并发缺陷；判断失败源于夹具、资源耗尽还是产品时序，再修对应层。
4. 改变测试或代码后运行受影响检查。没有新变化或未解决疑点时，复用有效证据，避免反复全量。

历史时间窗口问题包括空闲退出计时余量、先后发现实例、WebSocket 关闭竞速、会话快照落盘。修复应断言可观察行为并给合理等待条件，不把偶发失败直接列为“无需处理”。

## 验收边界

mock 编辑器、直接 SDK、stdio shim、真实 Godot、真实宿主与 GUI 是不同层。显式调用 tools/list 不能证明宿主自动重拉；握手成功不证明编辑器身份或游戏行为；headless 不证明截图/视觉结果。

运行命令使用目录中的测试工程；需要串行比较时可传 `-- xUnit.MaxParallelThreads=1`。发布门还包括五宿主 × 版本的通知行为与混跑矩阵，当前尚未完成。
