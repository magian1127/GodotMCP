# 验证

选择能够证明请求结果的最短验证链。

## 创作变更

1. 重新读取受影响的节点、场景、资源或设置。
2. 在适用时保存场景。
3. 对变更后的 GDScript 运行 `script_check`；变更跨文件时使用 `lsp_diagnostics(scope="project")`。
4. 如果有可用显示器，启动相关场景/项目。
5. 检查运行时状态或日志。仅在验证外观时使用截图。

## 游戏玩法变更

使用 godot-playtest：运行；时间因素重要时先冻结；注入有界输入；推进精确帧数或推进至满足条件；读取状态/日志；然后解除冻结，并且只停止由你启动的会话。

## 无头环境

对于依赖显示器的截图或游玩测试，`HEADLESS_UNSUPPORTED` 是有效的环境结果，而不是功能证明。仍要运行解析/LSP 检查和编辑器侧冒烟检查，并将视觉/运行时验收标记为待完成。

## 完成证据

报告项目路径、Godot 版本、已保存的产物、验证命令/工具以及具体的观察值。工具调用成功返回本身不能证明游戏行为正确。
