# 并行会话（多智能体并发）

多个智能体可以同时连接同一个 Godot 编辑器。两个系统会自动防止竞态——无需额外操作，但理解其行为有助于更快工作。发生竞争时，响应会变慢，**而不会损坏**。

## 后台发生了什么

- **变更锁** — 同一时间只执行一个变更。如果你的操作排队，响应时间会稍长，但不会报错。
- **场景租约** — 同一时间只有一个智能体“拥有”当前编辑器标签页。如果你操作的场景不同于当前标签页持有者，场景命令会排队等待标签页（最长约 8 秒，之后会发生抢占）。

## 精确路由规则

请求按以下三层顺序处理：

1. **场景租约首先路由。** 依赖标签页的命令——**包括读取**——如果目标场景不是当前标签页，会先为租约排队。
2. **只读命令绕过两种锁。** 不依赖当前标签页的读取会立即运行。
3. **变更按先进先出逐一串行化。** 两个变更不会重叠，会按到达顺序运行。

因此，目标为**非当前场景**的读取仍需等待租约，而不依赖当前标签页的读取则可以直接执行。

## 如何判断发生了竞争

当你调用 `scene_open` 而另一个会话持有当前标签页时，响应会包含类似以下提示：

> “注意：另一个会话当前正在编辑 res://forest.tscn……”

这表示你应重新安排工作顺序——先做与标签页无关的工作。在多会话负载下响应变慢属于竞争，不是失败。

## 与标签页无关的工作（无需等待）

无论场景是否竞争，以下操作都会立即执行：

- 读取和写入脚本
- 管理文件和文件夹
- 查询和设置项目设置
- 管理自动加载
- 读取控制台输出

## 依赖标签页的工作（可能排队）

以下操作需要当前标签页，发生竞争时可能等待：

- 在场景中创建、删除或修改节点
- 读取场景树或节点属性
- 保存场景

## 最佳实践

1. **创建前先检查。** 创建文件 / 场景前先读取已有内容——另一个智能体可能已经创建。使用 `scene_get_tree` 和宿主工作区文件读取工具进行调查。
2. **使用规范路径。** 将脚本放在 `scripts/`，场景放在 `scenes/`。已有子目录时不要把文件创建在项目根目录——没有协调的并行智能体可能造成重复。
3. **提前完成与标签页无关的工作。** 先写脚本、设置自动加载并配置项目设置，再创建场景节点。这样能尽量缩短占用窗口。
4. **批量设置属性。** 使用 `node_set_property` 的 batch 模式一次设置多个属性。每个工具调用都是一次竞争点，因此调用越少越好。
5. **不要与租约对抗。** 如果命令耗时数秒，这是租约系统正常工作。先切换到与标签页无关的任务，稍后再回来处理场景工作。
